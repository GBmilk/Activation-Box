# 激活盒子

> 把一段激活密钥投放进盒子，启动激活程序 —— 盒子会解析出完整的激活内容，并顺手复制到你的剪贴板。

一个纯静态、零依赖的单页小工具。打开 `index.html` 就能用，不需要安装任何东西，
不需要联网，也不需要后端。所有解析都在你自己的浏览器里完成。

**界面全中文**，**默认是白底**。自带 **3 种主题颜色 × 2 种明暗模式 = 6 套完整配色**，
右上角两条轴随意组合，切换柔和。**PC / 平板 / 手机**三档屏幕都做过适配与实测。
单次最多可解析 **5 MB** 的密钥。

## 它是什么

"激活盒子"是一个**主题化包装的文本解析小工具**。

用户在第一个输入框（**输入激活密钥**）里粘贴一段激活密钥，点击「启动激活」，
盒子会在第二个只读框（**激活结果**）里输出解析后的原始文本，**同时自动把结果复制到剪贴板**，
并在页面上弹出「已复制」的提示。

关于命名：这个工具底层做的是一次标准的文本解码运算（Base64 解码），
但**整个界面刻意不出现任何底层技术词汇**。对用户而言，它就是一个"投币 → 启动 → 取货"的盒子：
把密钥投进去，把内容取出来。这种"黑盒"隐喻让工具在面向非技术用户时更容易理解，
也让界面显得统一、友好、不像一个裸奔的开发工具。

## 外观矩阵：3 色 × 2 模式

外观由**两条互相独立的轴**决定，组合出 6 套配色：

| 外观 | 属性写法 | 页面底色 | 主色 | 主色上的文字 |
| --- | --- | --- | --- | --- |
| **森林绿 · 白天**（默认） | `forest` / `day` | `#ffffff` 纯白 | `#12854f` 深翠绿 | `#ffffff` 白 |
| **森林绿 · 黑夜** | `forest` / `night` | `#061410` 深林墨绿 | `#1fae6a` 翠绿 | `#04170f` 深绿 |
| **紫光蓝 · 白天** | `violet` / `day` | `#ffffff` 纯白 | `#4a5ae0` 靛蓝 | `#ffffff` 白 |
| **紫光蓝 · 黑夜** | `violet` / `night` | `#080b16` 深空藏蓝 | `#6d7dff` 靛紫蓝 | `#060a1c` 墨蓝 |
| **橙渐白 · 白天** | `amber` / `day` | `#ffffff` 纯白 | `#f2760c` 暖橙 | `#3b1a00` 焦褐 |
| **橙渐白 · 黑夜** | `amber` / `night` | `#17100a` 余烬褐黑 | `#f2760c` 暖橙 | `#2b1200` 焦褐 |

**轴一 · 主题颜色**决定"色相"：绿色系自然、蓝紫色系科技、橙黄色系温暖。

**轴二 · 明暗模式**决定"明度"：**白天一律是纯白底**，黑夜一律是深底浅字。

两者正交，所以你可以要"紫光蓝的色相 + 白天的明度"（白底 + 靛蓝按钮），
也可以要"橙渐白的色相 + 黑夜的明度"（余烬褐黑底 + 暖橙按钮）——
这是单轴主题（只能选一个颜色）做不到的表达力。

### 「白天 = 白底」这条语义是硬的

三套白天配色共用 `--bg: #ffffff`，主题色不出现在页面底色上，
而是落在**强调色、面板淡色、背景光晕**三处：

| 主题色 | 面板淡色 | 文本域底色 | 背景光晕 |
| --- | --- | --- | --- |
| 森林绿 | `rgba(240,250,244,.92)` 薄薄荷 | `#f3faf6` | 翠绿系 `rgba(31,174,106,.20)` |
| 紫光蓝 | `rgba(242,245,253,.92)` 薄薰衣草 | `#f5f7fe` | 靛蓝系 `rgba(109,125,255,.18)` |
| 橙渐白 | `rgba(253,246,238,.92)` 薄暖米 | `#fdf7ee` | 暖橙系 `rgba(251,146,60,.26)` |

这样做的理由：**"白天"应该是一个确定的承诺**。
用户点「白天」就是想要一张白纸，而不是"某种颜色的浅色版"。
底色统一白，个性交给强调色和光晕去表达，两件事互不干扰。

### 22 项语义色板

每套配色都完整覆盖：

```
页面底色 · 光晕强度 · 面板底色 · 文本域底色 · 文本域聚焦底色
边框 · 强调边框 · 正文色 · 次级文字色 · 弱化文字色
主色 · 辅色 · 主色浅底 · 主色上的文字色
成功色 · 警告色 · 错误色 · 聚焦光环色 · 阴影色
提示条底色 · 提示条文字色 · 三颗背景光晕色
```

其中「主色上的文字色」（`--on-accent`）是这套矩阵里最容易做错的一环：
深色外观下主色是亮绿，需要**深色文字**压上去；浅色外观下主色变成深绿，就需要**白色文字**。
不区分这一点，浅色外观的按钮会出现"白字压亮绿"或"深字压深绿"的对比度事故。
所以每一套配色都单独指定了 `--on-accent`。

## 响应式布局

目标：**PC、平板、手机**三档都能正常显示、好点、不溢出。

### 三档分别是

| 档位 | 宽度 | 版心 | 关键变化 |
| --- | --- | --- | --- |
| **PC** | ≥ 1025px | 900px 居中 | 留白最大，切换器与品牌同行靠右 |
| **平板** | 641 – 1024px | 820px 居中 | 留白由 `clamp()` 收紧，结构不变 |
| **手机** | ≤ 640px | 整宽（约 14px 内边距） | 切换器换行撑满、主按钮撑满、输入框字号提到 16px |
| 横屏手机 | 高度 ≤ 520px | 同手机 | 压缩头部留白与文本域高度 |

### 三个关键决定

**① 留白用 `clamp()` 连续缩放，而不是靠断点跳变。**

```css
.page {
  max-width: 900px;
  padding-top:    calc(clamp(34px, 6vw, 56px)  + env(safe-area-inset-top, 0px));
  padding-bottom: calc(clamp(28px, 5vw, 48px)  + env(safe-area-inset-bottom, 0px));
  padding-left:   calc(clamp(14px, 3.6vw, 24px) + env(safe-area-inset-left, 0px));
  padding-right:  calc(clamp(14px, 3.6vw, 24px) + env(safe-area-inset-right, 0px));
}
```

断点只负责**结构性变化**（要不要换行、要不要撑满），尺寸的微调全部交给 `clamp()`。
于是拖动窗口在两档之间来回时，是连续变化而不是"跳一下"。
同样的手法也用在了标题字号、品牌图标尺寸、面板内边距与圆角上。

**② 手机上的换行交给 flex 自己判断，再用 `margin-left: auto` 兜住对齐。**

```css
.hero__top { display: flex; flex-wrap: wrap; }
.brand     { flex: 1 1 auto; min-width: 0; }
.switchers { flex: none; margin-left: auto; }   /* 换到第二行时依然贴右 */
```

宽度够的时候切换器和品牌同行、贴右；放不下时自动折到第二行、依然是右对齐。
这一条让 641 – 1024px 的平板区间**不需要任何额外断点**就能正常工作。

**③ 手机上的输入框字号提到 16px —— 这是修 iOS 的一个具体毛病。**

iOS Safari 在聚焦字号小于 16px 的输入框时，会自动把整个页面放大，
用户的视线会被顶走，还得手动缩回来。从根上避免它的唯一办法就是把字号提到 16px：

```css
@media (max-width: 640px) {
  .box__area { font-size: 16px; }
}
```

### 触摸设备单独处理

用 `@media (hover: none) and (pointer: coarse)` 识别触摸设备，而不是靠宽度猜：

```css
@media (hover: none) and (pointer: coarse) {
  .seg__opt { min-height: 40px; }    /* 切换器选项放大到好按 */
  .btn--link { min-height: 40px; }   /* 「清空 / 复制结果」放大 */
  .btn--lg { min-height: 48px; }     /* 主按钮放大 */
  .btn__kbd { display: none; }       /* 触屏没有物理键盘，键位提示没意义 */
}
```

在手机上把「清空」「复制结果」这类小文字按钮按 24px 高去点，是很难点中的。
另外 `Ctrl / ↵` 的键位提示在触屏上只会占地方，直接隐藏。

### 刘海屏与手势条

`viewport` 加了 `viewport-fit=cover`，页面四周用 `env(safe-area-inset-*)` 让开安全区，
底部浮动提示也一起抬高，不会被 iPhone 的手势条压住：

```css
.toast { bottom: calc(34px + env(safe-area-inset-bottom, 0px)); }
```

### 本页另外处理的细节

| 问题 | 处理 |
| --- | --- |
| 移动端键盘弹出后 `100vh` 会算错 | 文本域高度用 `dvh`（动态视口）并保留 `vh` 作为回退 |
| iOS 横屏自动放大字号 | `html { -webkit-text-size-adjust: 100% }` |
| 长密钥撑破容器 | 文本域 `word-break: break-word` + `overflow-wrap: anywhere` |
| 视口外横向滚动 | 背景光晕层 `overflow: hidden`，`body { overflow-x: hidden }` |
| 极窄屏（≤360px） | 单独一档，再收小切换器字号与内边距 |
| 短横屏（高度 ≤520px） | 单独一档，压缩头部留白与文本域最小高度 |

### 实测过的尺寸

| 设备 | 视口 | 结果 |
| --- | --- | --- |
| 桌面大屏 | 1440 × 900 | 版心 900 居中，两条轴与品牌同行 |
| 桌面笔记本 | 1280 × 820 | 同上 |
| 平板竖屏（iPad Air） | 834 × 1112 | 版心收到 820，整页一屏可见 |
| 平板横屏 | 1024 × 768 | 切换器保持同行 |
| 手机 | 390 × 844 | 切换器换行撑满、主按钮撑满 |
| 小手机 | 360 × 640 | 布局不外溢，文案正常折行 |
| 手机横屏 | 844 × 390 | 压缩纵向留白，切换器回到同行 |

> **一个实测经验**：Windows 上的 Chrome / Edge（含无头模式）会把窗口宽度**强制不小于约 500px**。
> 直接用 `--window-size=390,844` 截图，页面其实是按 ~500px 排版的，
> 然后被裁到 390px —— 看起来就像"手机端溢出了"，其实是截图工具的假象。
> 要测真实的窄视口，应该用一个 `width: 390px` 的 `<iframe>` 套住页面再截图。

## 项目结构

```
Activation Box/
├── index.html           页面骨架：语义结构 + 两条外观切换轴 + 双文本域 + 状态条 + 浮动提示
├── css/
│   └── style.css        全部样式：设计令牌、6 套配色、布局、组件、动效、响应式
├── js/
│   ├── theme-init.js    外观预热：在首屏绘制前上色，消除闪烁（必须放 <head>）
│   └── app.js           全部逻辑：外观切换 + 校验 → 解析 → 输出 → 复制 → 反馈
└── README.md            本文件
```

四层职责严格分离：

- **HTML** 只描述"页面上有什么"，不写内联样式；唯一的脚本引用是 `theme-init.js`；
- **CSS** 只描述"长什么样"，全部配色走 CSS 变量，换外观只需换一组变量；
- **JS** 只描述"怎么动"，不拼接 HTML 字符串、不直接改内联样式，只切 class 和属性；
- **`theme-init.js`** 只做一件事：抢在首次绘制前把外观属性挂到 `<html>` 上。

> 为什么外观预热要单独一个文件？因为它必须在**样式表之前、同步执行**，
> 而 `app.js` 放在 `</body>` 前（此时页面已经画过一帧了）。
> 放到同一个文件里做不到"提前"，写成 `<head>` 内联脚本又违背"不写内联脚本"的约定，
> 所以拆成一个自包含的极小文件。

## 快速开始

### 方式一：直接双击打开（最简单）

```text
双击 index.html
```

立刻就能用。注意：在 `file://` 协议下，部分浏览器会收紧剪贴板权限，
此时自动复制可能被拦截 —— 盒子会提示"自动复制被浏览器拦截，请点「复制结果」"，
点一下输出框上方的「复制结果」按钮即可完成。功能本身不受影响。

### 方式二：本地起一个静态服务器（推荐，剪贴板体验最完整）

```bash
# Python 3
python -m http.server 8080

# 或者 Node.js
npx serve .
```

然后访问 `http://localhost:8080`。
在 `http://localhost` 这个安全上下文里，现代浏览器的异步剪贴板 API 可以正常工作，
自动复制几乎百发百中。

用这种方式还可以**在同一局域网里用手机扫码访问**（把 `localhost` 换成电脑的局域网 IP），
直接在真机上检查响应式效果 —— 比在桌面浏览器里缩窗口靠谱得多。

### 方式三：丢到任意静态托管

把整个目录原样上传到 GitHub Pages、Netlify、Vercel、对象存储或公司内网静态目录即可。
没有构建步骤，没有环境变量，没有路由要求。

## 使用说明

### 标准流程

1. **投币** —— 在「输入激活密钥」框里粘贴你的激活密钥。
   密钥里有换行、缩进、空格都没关系，盒子会自己整理干净。

2. **启动** —— 点击「启动激活」，或直接按 `Ctrl + Enter`（macOS 用 `⌘ + Enter`）。

3. **取货** —— 解析结果出现在「激活结果」框里，同时被自动复制到剪贴板，
   右下角会弹出「已复制到剪贴板！」的提示条。

### 调外观

页面**右上角**是两条独立的外观切换轴，纵向排列、等宽对齐：

```
              ┌─────────────────────────────────────┐
              │  ● 森林绿  │  ● 紫光蓝  │  ● 橙渐白  │  ← 轴一：主题颜色
              └─────────────────────────────────────┘
                  ┌───────────────────────────┐
                  │   ☀ 白天    │   ☾ 黑夜    │      ← 轴二：明暗模式
                  └───────────────────────────┘
```

- **主题颜色**：点色票选色相，绿色系自然、蓝紫色系科技、橙黄色系温暖；
- **明暗模式**：`☀ 白天` 是**纯白底 + 深色文字**，`☾ 黑夜` 是深底 + 浅色文字。

两条轴互不影响，随便组合。每次点击，整页配色立刻平滑过渡：
胶囊滑过去、颜色收拢、背景光晕换色。两个选择分别被记住，下次打开还是这个组合。

> 默认是「森林绿 · 白天」，也就是一张白底页面。
> 第一次打开就是这个样子，不需要先点任何按钮。

> 色票是**固定的**，不会跟着当前外观变色 ——
> 这样无论你现在用哪套配色，都能一眼认出每个颜色选项代表什么。

### 辅助操作

| 按钮 | 位置 | 作用 |
| --- | --- | --- |

## 外观系统详解

这一节是本项目的核心，值得单独讲清楚。

### 1. 两个属性驱动全部

整套换肤只依赖 `<html>` 上的两个属性：

```html
<html lang="zh-CN" data-theme="forest" data-mode="day">
```

- `data-theme` = 色相轴：`forest` / `violet` / `amber`
- `data-mode` = 明度轴：`day` / `night`

CSS 里对应 6 块变量声明，块名就是组合名：

```css
html,
html[data-theme="forest"][data-mode="day"]   { /* ① 森林绿 · 白天（默认，白底） */ }
html[data-theme="forest"][data-mode="night"] { /* ② 森林绿 · 黑夜 */ }
html[data-theme="violet"][data-mode="day"]   { /* ③ 紫光蓝 · 白天 */ }
html[data-theme="violet"][data-mode="night"] { /* ④ 紫光蓝 · 黑夜 */ }
html[data-theme="amber"][data-mode="day"]    { /* ⑤ 橙渐白 · 白天 */ }
html[data-theme="amber"][data-mode="night"]  { /* ⑥ 橙渐白 · 黑夜 */ }
```

JS 里真正"换肤"的只有一行：

```js
document.documentElement.setAttribute(attr, value);
```

改完这一行，剩下的全部交给 CSS。JS 不做任何逐帧计算，
所以切换是**即时**的 —— 属性一变，浏览器下一帧就是新配色。

> **为什么默认配色同时写在裸 `html` 选择器上？**
> 因为 `html[data-theme=…][data-mode=…]` 这种双属性选择器的特异性是 `(0,2,1)`，
> 而裸 `html` 只有 `(0,0,1)`。把默认配色同时挂在 `html` 上，
> 即使两个属性因为任何原因都缺失或写错，页面也会回落到「森林绿 · 白天」——
> 也就是一张白纸，而不是一块无色白板。
>
> 用「选择器列表」写在同一块里，既拿到了两种特异性，又避免了把 22 项色值抄两遍。
> 另外 `html { background-color: var(--bg, #ffffff) }` 还留了最后一道保险：
> 连变量都没生效时，画布依然是白的。

### 2. 两条轴共用一套交互代码

两条轴的交互逻辑完全一样（收集选项 → 记录选中 → 移动胶囊 → 持久化），
所以抽成了一个工厂函数 `initSwitch`，各传一份配置：

```js
const themeSwitch = initSwitch({
  root: els.themeSwitch, glider: els.themeGlider,
  attr: 'data-theme', storageKey: 'activation-box-theme',
  allowed: THEMES, fallback: DEFAULT_THEME,
});

const modeSwitch = initSwitch({
  root: els.modeSwitch, glider: els.modeGlider,
  attr: 'data-mode', storageKey: 'activation-box-mode',
  allowed: MODES, fallback: DEFAULT_MODE,
});
```

`allowed` 这个白名单同时承担两个职责：**校验**（`localStorage` 里被改脏的值会被丢弃并回落到
`fallback`）和**兜底**。每条轴独立持久化，互不干扰 —— 改色相不会重置明暗，反之亦然。

想再加第三条轴（比如"圆角风格""字号大小"），只要在 HTML 里放一个 `.seg`、
在 CSS 里写一组 `html[data-xxx=…]`，然后 `initSwitch` 一次即可，逻辑代码零改动。

### 3. 过渡是怎么做到"自然流畅"的

这是最容易踩坑的地方。有三条关键决策。

**决策一：主题色一律使用纯色，不用渐变。**

CSS 的 `background-image`（包括所有 `linear-gradient` / `radial-gradient`）
**无法参与 `transition` 过渡** —— 换外观时它会硬切，产生视觉上的"跳变"。

所以本项目把主题色全部收敛成纯色：

```css
/* ✗ 这么做换外观时会硬切 */
.btn--primary { background-image: linear-gradient(135deg, var(--a), var(--b)); }

/* ✓ 纯色可以平滑过渡 */
.btn--primary { background-color: var(--accent); }
```

那"渐变质感"怎么补回来？用**静态渐变叠加层**：

```css
.btn--primary::after {
  background-image: linear-gradient(180deg,
    rgba(255,255,255,.22) 0%, rgba(255,255,255,0) 64%);
}
```

这层高光是固定不变的（不随外观变化），所以它不需要过渡，
只负责给按钮加一点顶部受光感。主色还是走 `background-color`，照样平滑。

背景光晕同理：`.backdrop__wash` 用一张**静态的白色径向渐变**，
真正参与过渡的是它的 `opacity` —— 深色外观压到 `.05` 左右，
白天外观直接归零（白底上叠白色没有任何意义，索性连合成层都省掉）。

**决策二：全站统一过渡时长，保证同步。**

```css
:root {
  --t-dur:  .36s;
  --t-ease: cubic-bezier(.4, 0, .22, 1);
}
```

所有承载主题色的元素，在样式表末尾用**同一条 transition** 统一覆盖：

```css
body, .panel, .box, .btn, .status, .toast, .seg, /* ... */
{
  transition:
    background-color var(--t-dur) var(--t-ease),
    border-color     var(--t-dur) var(--t-ease),
    color            var(--t-dur) var(--t-ease),
    box-shadow       var(--t-dur) var(--t-ease),
    transform        .16s ease;
}
```

为什么节奏必须一致？如果面板用 `.5s`、按钮用 `.2s`、文字用 `.6s`，
换外观时就会出现"按钮先到位、面板还在半路、文字最后才追上"的拖泥带水感。
统一成 `.36s` 之后，所有部件像被同一只手同时拧了一下 —— 这才叫"自然"。

`.36s` 加缓出曲线是一个经过权衡的值：足够柔和，又足够快 ——
点击后几乎立刻感知到反馈，不会让人怀疑"我点到了吗"。

**决策三：把"交互反馈"和"主题过渡"解耦。**

同一个属性（比如 `border-color`）既要承担 hover 的快速反馈，
又要承担换外观的慢速过渡，会互相打架。解决方式是让它们作用在**不同的属性**上：

```css
/* hover 反馈走 box-shadow，快（.16s） */
.box:hover { box-shadow: inset 0 0 0 1px var(--border-strong); }

/* 主题过渡走 border-color，慢（.36s） */
.box { border-color: var(--border); }
```

这样鼠标划过时依然干脆利落，换外观时依然柔和，两边都不将就。

### 4. 滑动指示器

每条轴的选中态由一枚绝对定位的胶囊（`.seg__glider`）承担。
JS 只负责算出目标位置并写进去：

```js
glider.style.width = opt.offsetWidth + 'px';
glider.style.transform = 'translateX(' + opt.offsetLeft + 'px)';
```

移动本身交给 CSS 的 `.45s` 弹性曲线：

```css
.seg__glider {
  transition: transform .45s cubic-bezier(.22, .9, .28, 1.04),
              width     .45s cubic-bezier(.22, .9, .28, 1.04);
}
```

比颜色过渡稍慢一点点，还带一点越界回弹 —— 于是"点一下"这个动作里，
先看到胶囊滑过去，再看到整页颜色收拢，有了先后层次，比所有东西同时动更有质感。

首屏定位时要临时关掉过渡，否则会看到胶囊从左边缘滑到目标位的"入场动画"：

```js
if (instant) glider.style.transition = 'none';
// ...写入位置...
void glider.offsetWidth;      // 强制重排，让定位立即生效
glider.style.transition = ''; // 还原，交还给 CSS
```

尺寸变化时也要重新对齐 —— 而**窗口缩放、字体加载完成、响应式断点导致按钮变宽**，
都会改变选项的宽度。所以用 `ResizeObserver` 监听每条轴自身的尺寸，
比监听 `window.resize` 更可靠（后者漏掉字体加载和容器变化）。

### 5. 消除首屏闪烁

如果外观只由 `app.js` 决定，页面会先用 HTML 上写的默认外观画一帧，
等 `app.js` 执行完再切成用户实际选择的外观 —— 那一帧就是"闪白"。
在「黑夜」这类深色外观下尤其刺眼（白底闪成深底）。

`js/theme-init.js` 放在 `<head>` 里、样式表之前，抢在首次绘制前把两个属性都写好：

```js
var ATTRS = [
  { attr: 'data-theme', key: 'activation-box-theme', allowed: ['forest', 'violet', 'amber'] },
  { attr: 'data-mode',  key: 'activation-box-mode',  allowed: ['day', 'night'] }
];
for (var i = 0; i < ATTRS.length; i++) { /* 读 localStorage，白名单校验后写属性 */ }
```

因为这时 CSS 还没加载，浏览器压根没画过任何东西，自然也就没有闪烁。

### 6. 提示条为什么用固定色

`.toast` 的底色在全部 6 套配色里**都是深色**（深绿 / 墨蓝 / 褐黑），
因为它浮在页面最上层，深色底 + 浅色字在明暗两种外观下都能保证可读性。

既然底色固定是深的，图标就用**固定的亮色**（`#34d399` 绿 / `#fb7185` 红 / `#fbbf24` 黄），
而不是跟随 `--ok` / `--err` / `--warn`：

```css
.toast__icon { background-color: #34d399; color: #052018; }
```

否则白天外观下 `--ok` 会变成深绿（为了在白底上能当文字色），
放到深色的提示条里就会糊成一团。一个固定值省掉了 9 个只服务图标的变量，
也保证永远清晰。

同理，`.status--ok` 这类**在浅底上当文字用**的成功色才跟随 `--ok`，两者职责不混。

### 7. 动效降级

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```

系统开了"减弱动态效果"的用户，换外观会变成瞬时切换（功能完全不受影响），
背景光晕也不再漂浮。这是无障碍的基本礼貌。

## 交互细节

这些细节在源码里都被显式实现了，值得说明：

**1. 结果为空时按钮自动置灰。**
「复制结果」按钮在没有解析结果时是 `disabled` 的，避免用户点了没反应。

**2. 输入即清理错误态。**
上一次报错后状态条是红色的，用户一改动输入内容，红色提示立刻回到中性的"已就绪"，
不会让旧的错误信息一直挂着吓人。

**3. 错误反馈是三重的。**
状态条变色 + 文字说明 + 输入框左右抖动一下。抖动做了 `void offsetWidth` 强制重排，
保证连续多次触发也能重新播放动画。

**4. "激活中"的过渡。**
点击后按钮会短暂进入忙碌态（图标旋转 + 文字变成「激活中…」），
给异步的剪贴板写入留出视觉缓冲，避免"点了没反应"的错觉。

**5. 实时字符计数。**
两个框底部都显示字符数，输入框实时更新，方便确认粘贴是否完整。

**6. 外观会被记住，但密钥不会。**
两条轴的选择写入 `localStorage`，其余状态一律留在内存里，关掉页面就没了。

**7. 复制成功与复制失败是两条路径。**
复制成功 → 绿色状态条 + 绿色「已复制」提示。
复制被拦截 → 结果照常输出，状态条用琥珀色提示，并引导用户改用「复制结果」按钮。
**解析结果绝不会因为复制失败而丢失。**

**8. 浏览器的界面配色会跟着走。**
切换外观后（等过渡走完），会把新底色同步给 `<meta name="theme-color">`，
手机上地址栏 / 状态栏的颜色会一起变，不会出现"页面白色、状态栏还是深绿"的割裂感。
两条轴共用同一个同步函数，用 `setTimeout` 合并短时间内的连续切换，避免反复读写。

## 错误提示一览

所有提示均为中文、口语化，并且会告诉用户**下一步该做什么**，而不是甩一个技术术语。

| 触发场景 | 页面提示 |
| --- | --- |
| 输入框为空 | 盒子是空的 —— 请先粘贴你的激活密钥。 |
| 输入只有空白字符 | 密钥里只有空白字符，请检查是否复制完整。 |
| 内容超过 5 MB | 密钥体积过大（超过 5 MB），请确认内容是否正确。 |
| 出现非法字符 | 密钥中出现了无法识别的字符「x」，请重新复制。 |
| 长度异常（某 4 字符组只剩 1 个） | 密钥长度不合法，可能在复制时被截断了，请重新复制。 |
| 结构损坏无法解析 | 这段密钥无法被盒子解析，请确认它是一段完整的激活密钥。 |
| 复制成功 | 已复制到剪贴板！（状态条：激活成功！已解析出 N 个字符，并复制到剪贴板。） |
| 复制被浏览器拦截 | 复制没有成功，请手动选中结果后使用 Ctrl + C。（状态条：激活成功！已解析出 N 个字符，但自动复制被浏览器拦截，请点「复制结果」。） |
| 点击清空 | 盒子已清空，等待新的激活密钥。 |

> 提示的设计原则：**先说发生了什么，再说怎么办。**
> 例如不会只说"解码失败"，而是说"可能在复制时被截断了，请重新复制" —— 后者用户能据以行动。

## 设计说明

### 视觉语言

- **干净的浅色基调**：默认就是白底。主题个性不靠大面积染色，而是靠
  「强调色 + 面板淡色 + 背景光晕」三处点到为止地表达。
- **背景光晕**：每套配色都由「底色 + 一层光晕 + 三颗模糊色球」构成，
  色球以 22 秒的周期缓慢漂浮。白天外观下它们是很淡的一层氛围色，黑夜外观下则是主要的氛围来源。
- **玻璃拟态面板**：主面板使用 `backdrop-filter: blur(18px)` 加半透明背景，
  浮在光晕之上，层次清晰 —— 这一点在 6 套配色里都成立。
- **主色即品牌色**：品牌标识、主按钮、编号徽标、结果色带都取 `--accent`，
  所以换外观时整个页面的"性格"会一起变，而不是只换背景。
- **输入 / 输出的视觉区分**：输入框是普通描边；结果框额外加一条 3px 的左侧色带 ——
  待机时是中性色，有结果后变成强调色，一眼就能看出"盒子出货了"。
- **克制的动效**：只有四处动画 —— 背景光晕漂浮、状态点脉冲、输入框抖动报错、
  切换器胶囊滑动。全部在 `prefers-reduced-motion: reduce` 下自动关闭。

### 版面节奏

```
【顶部】  ✚ 激活盒子 / 密钥解析工具          ┌ 主题颜色切换器 ┐
                                            └ 明暗模式切换器 ┘
          一句说明文案

【输入】  01  输入激活密钥  ······························ 清空
          可编辑文本域
          底栏：只有「0 字符」计数器（提示文字已移除）

【操作】  [ ⚡ 启动激活  Ctrl ↵ ]                            ← 视觉重心
          解析结果将自动复制到剪贴板

【输出】  02  激活结果  [只读] ························· 复制结果
     ┃    只读文本域（左侧色带标识"已出货"）
     ┃    底栏：「等待激活」+「0 字符」

【状态】  ● 盒子已就绪，等待你的激活密钥。

【页脚】  © 激活盒子 · 保留所有权利                          ← 中英两行
          © Activation Box · All rights reserved.
```

编号 `01 / 02` 和唯一的实心主按钮，把"粘贴 → 点按钮 → 拿结果"这条动线讲得很清楚。

### 两条轴为什么纵向排、还要等宽

两条轴横向并排的话，总宽度会到 400px 以上，在 900px 的版心内会和左侧品牌名挤在一起；
在平板上更会直接挤爆。纵向排布后，两块控件共用同一个宽度（由较宽的那条决定），
右对齐成一列，既省了横向空间，也在视觉上明确了它们是同一组"外观设置"。

实现上靠三行 CSS：

```css
.switchers { display: flex; flex-direction: column; width: max-content; }
.seg       { align-self: stretch; }   /* 两条轴等宽 */
.seg--mode .seg__opt { flex: 1; }     /* 两个选项平分 */
```

手机（≤640px）时 `.switchers` 变成整行宽，两条轴一起撑满，手指好点。

界面刻意避开了底层技术名词，改用主题化措辞。这是本项目的核心要求之一。

| 深色配色 | 黑夜 |

### 界面全中文

**界面上不出现英文**，包括：

- 品牌副标题：`密钥解析工具`（不是字样排开的英文名）
- 浏览器标签标题：`激活盒子 · 密钥解析工具`
- 输入框提示、状态条、报错文案、页脚正文 —— 全部中文

同样**不出现**：`Base64`、`编码`、`解码`、`转换器`、`Converter`、`decode`、`encode`、
`亮色模式`、`暗色模式` 等字样。

有三处是刻意保留的非中文，都属于"符号"而非"文案"：

| 位置 | 内容 | 为什么保留 |
| --- | --- | --- |
| 主按钮键帽 | `Ctrl` `↵` | 键盘上实际印着的键名，换中文反而对不上键位；触屏设备上会自动隐藏 |
| 超限报错 | `5 MB` | 国际单位，中文语境下的通用写法（不会写成"5 兆"） |
| 页脚版权行 | `© Activation Box · All rights reserved.` | 版权声明惯例用英文再写一行；这是页面底部唯一的一行英文 |

页脚的版权信息是**中英两行**：

```html
<p class="foot__cn">© 激活盒子 · 保留所有权利</p>
<p class="foot__en" lang="en">© Activation Box · All rights reserved.</p>
```

英文那一行标了 `lang="en"`，这样读屏软件会用英文发音规则去读它，
而不是拿中文规则硬念一段英文。

> 代码里的注释、文件名、`localStorage` 键名、CSS 类名依旧是英文 ——
> 它们不属于"界面内容"，也不出现在用户眼前。

## 技术实现

### 解析流程

```
原始输入
   │
   ├─ 空 / 超长 检查 ────────────────► 立即返回友好提示
   │
   ├─ 清理：去掉 \s 与全角空格 U+3000
   ├─ 归一：- → + ，_ → /
   ├─ 白名单扫描：抓出第一个非法字符并精确报错
   ├─ 填充修正：剥掉尾部 = ，按 4 的倍数重新补齐
   │    └─ 若 length % 4 === 1 ──────► 判定为"被截断"
   │
   ├─ atob() 还原字节流
   ├─ TextDecoder('utf-8', { fatal: true })
   │    └─ 若非合法 UTF-8 ───────────► 退化为单字节映射（Latin-1）
   ├─ 剥离 UTF-8 BOM
   │
   ▼
输出到只读框 → 自动复制 → 状态条 + 浮动提示
```

### 为什么 UTF-8 要"严格优先"

`atob()` 返回的是**字节串**，不是文本。如果直接用 `atob(x)` 而不做字节→字符的转换，
中文会变成乱码。常见的错误写法是 `decodeURIComponent(escape(atob(x)))`，
但 `escape` 早已废弃且对超范围码点处理有缺陷。

本项目改用 `TextDecoder`：

```js
new TextDecoder('utf-8', { fatal: true }).decode(bytes)
```

`fatal: true` 表示遇到非法 UTF-8 序列就抛错，而不是静默替换成 `�`。
捕获到这个错误后，说明这份密钥里装的不是 UTF-8 文本（可能是二进制或其它编码），
此时退化为按单字节映射，**至少把内容原样呈现出来，不吞掉任何数据**，同时不报"失败"吓用户。

### 剪贴板的双保险

```js
// 方案一：异步剪贴板 API —— 需要安全上下文（https 或 localhost）
await navigator.clipboard.writeText(text);

// 方案二：临时 textarea + execCommand —— 兼容 file:// 与旧浏览器
helper.select();
document.execCommand('copy');
```

方案二里还做了一件容易被忽略的事：**保存并恢复用户原有的选区**。
否则用户辛苦选中的一段文字会因为这行代码被清掉，体验很差。

两个方案都失败时不会静默：状态条和提示条都会告诉用户改用「复制结果」按钮或手动 `Ctrl + C`。

### 状态与外观的存储

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `activation-box-theme` | `forest` / `violet` / `amber` | 色相轴 |
| `activation-box-mode` | `day` / `night` | 明度轴 |

- 读写都包在 `try/catch` 里 —— 隐私模式下 `localStorage` 可能直接抛错，
  这时静默降级为默认外观（森林绿 + 白天），功能不受影响。
- 读取时用白名单校验，被改脏的值一律回落到 `fallback`。
- 其余状态（密钥、结果）**一律不落盘**，关闭页面即遗忘。
- `<meta name="theme-color">` 会在切换后同步当前底色，让移动端浏览器界面保持一致。

### 为什么不用 `@property`

有一种更"炫"的做法：用 CSS 的 `@property` 注册自定义属性，
让渐变本身也能插值过渡。但 `@property` 需要 Chrome 85+ / Safari 16.4+ / Firefox 128+，
且在低版本下会静默失效、表现为硬切。

本项目的做法（**纯色 + 元素级 transition**）在支持 CSS 变量的所有浏览器上都能工作，
覆盖面更广，行为也更可预测 —— 代价只是需要把渐变拆成"纯色底 + 静态高光层"。
这是一次刻意的取舍：优先保证"所有人都流畅"，而不是"新浏览器里更花哨"。

## 浏览器兼容性

| 浏览器 | 最低版本 | 说明 |
| --- | --- | --- |
| Chrome / Edge | 90+ | 完整支持，自动复制体验最佳 |
| Firefox | 88+ | 完整支持 |
| Safari (macOS / iOS) | 15.4+ | 完整支持，已针对 iOS 的聚焦放大与安全区单独处理 |
| Android Chrome | 近三年主流版本 | 完整支持 |
| IE 11 | ❌ | 不支持，使用了 `TextDecoder` / `backdrop-filter` / CSS 变量 |

用到的现代特性：CSS 自定义属性、`clamp()`、`dvh`、`env()`、`backdrop-filter`、
`color-mix()`、`TextDecoder`、`navigator.clipboard`、`ResizeObserver`、`async/await`。

降级策略：

- `clamp()` / `dvh` / `env()` 不被支持时，浏览器会丢弃该条声明，
  版面回到基础值（`padding` 会退到 0 之外的基础布局、文本域高度退回 `vh`），**不会白屏**；
- `color-mix()` 仅用于状态条与键帽的配色微调，**不支持时自然回落到基础配色**；
- 剪贴板 API 不支持时自动走 `execCommand` 兜底；
- `ResizeObserver` 不可用时退化为监听 `window.resize`；
- `prefers-reduced-motion` 时关闭全部动画。

因此实际最低要求比表格中的版本更宽松。**换肤过渡与响应式布局本身都不依赖特别新的特性**，
核心是 CSS 变量 + transition + media query，2016 年之后的浏览器就能完整享受。

## 自定义指南

### 微调某套配色的颜色

所有颜色集中在 `css/style.css` 顶部的 6 个变量块里。以默认的「森林绿 · 白天」为例：

```css
html,
html[data-theme="forest"][data-mode="day"] {
  color-scheme: light;
  --bg:        #ffffff;     /* 页面底色：纯白 */
  --panel:     rgba(240, 250, 244, .92);
  --text:      #0c2318;
  --accent:    #12854f;     /* 主色：按钮、编号、品牌标识 */
  --accent-2:  #0d7a49;     /* 辅色：结果框状态色带、强调文字 */
  --on-accent: #ffffff;     /* 主色之上的文字色 */
  /* ... */
}
```

改完记得**同时检查另外 5 套配色**，保持各套的视觉重量接近，切换时才不会有落差。
尤其是 `--on-accent`：主色变浅了就把文字改深，主色变深了就把文字改浅。

### 如果你更喜欢有底色的「白天」

现在的三套白天配色共用 `--bg: #ffffff`。如果你希望「森林绿 · 白天」带一点薄荷底，
把它那一块的 `--bg` 改成 `#eff8f2`、`--panel` 改成 `rgba(255,255,255,.86)` 就行 ——
但注意这时 `--glow-opacity` 要一起开回来（比如 `.85`），否则淡色底会显得很平。
另外两套同理。

### 调整过渡节奏

```css
:root {
  --t-dur:  .36s;                          /* 外观过渡时长 */
  --t-ease: cubic-bezier(.4, 0, .22, 1);   /* 缓动曲线 */
}
```

想要更"慢动作"的柔化效果，把 `--t-dur` 调到 `.6s`；
想要更干脆，调到 `.22s`。改这一个值，全站同步生效。

切换器胶囊的弹性节奏是单独写死的（`.45s` + 回弹曲线），
在 `.seg__glider` 那两条规则里，想调可以单独改。

### 调整响应式断点

结构性的断点集中在 `css/style.css` 第 13 节，一共四处：

```css
@media (hover: none) and (pointer: coarse) { /* 触摸设备：放大点击目标 */ }
@media (max-width: 640px)   { /* 手机：换行 + 撑满 + 输入框 16px */ }
@media (max-width: 360px)   { /* 极窄手机：再收一档 */ }
@media (max-height: 520px) and (orientation: landscape) { /* 横屏手机 */ }
```

如果你的目标设备更特殊（比如车载屏 800×480），想调的是**尺寸**，优先改第 4 节的
`clamp()` 区间；想调的是**结构**（比如 800px 就要换行），再动上面这些断点。

### 新增一种主题颜色（要配两套）

假设要加一套「玫红」，它需要**白天版和黑夜版两套配色**：

**① 在 `css/style.css` 里追加两个变量块**

```css
html[data-theme="rose"][data-mode="day"] {
  color-scheme: light;
  --bg: #ffffff;
  --glow-opacity: 0;
  --panel: rgba(253, 241, 245, .92);
  --box: #fdf1f5;
  /* ...把 22 项全部覆盖... */
  --accent: #c9256a;          /* 浅底上要更深，白字才压得住 */
  --accent-2: #a81b57;
  --on-accent: #ffffff;
  --orb-a: rgba(244, 63, 126, .26);
  --orb-b: rgba(253, 164, 192, .30);
  --orb-c: rgba(200, 60, 120, .20);
}

html[data-theme="rose"][data-mode="night"] {
  color-scheme: dark;
  --bg: #150810;
  --glow-opacity: .06;
  /* ...把 22 项全部覆盖... */
  --accent: #f43f7e;
  --accent-2: #fda4c0;
  --on-accent: #2a0413;
  --orb-a: rgba(244, 63, 126, .42);
  --orb-b: rgba(253, 164, 192, .26);
  --orb-c: rgba(140, 20, 80, .36);
}
```

**② 在 `index.html` 的色相轴里加一个选项**

```html
<button type="button" class="seg__opt" role="radio"
        aria-checked="false" tabindex="-1" data-value="rose">
  <span class="seg__dot" data-swatch="rose" aria-hidden="true"></span>
  <span class="seg__label">玫红</span>
</button>
```

**③ 给它加一枚色票（固定渐变，不随外观变化）**

```css
.seg__dot[data-swatch="rose"] {
  background-image: linear-gradient(135deg, #f43f7e 0%, #fda4c0 100%);
}
```

**④ 把代号登记进 JS 的白名单**

```js
// js/theme-init.js
{ attr: 'data-theme', key: 'activation-box-theme', allowed: ['forest', 'violet', 'amber', 'rose'] }

// js/app.js
const THEMES = ['forest', 'violet', 'amber', 'rose'];
const THEME_LABEL = { /* ... */ rose: '玫红' };
```

加到第 4 个颜色之后，手机上三个选项可能一行放不下 ——
如果出现拥挤，可以隐藏文字只留色票（给 `.seg__label` 加 `display: none`）。

### 新增一种明暗模式

如果还想要「深夜」（比黑夜更暗、对比度更低），照同样的四步来：
在明度轴上加选项 `data-value="deep"`，写 3 个 `html[data-theme="x"][data-mode="deep"]` 块，
再把它加进 `MODES` 与 `theme-init.js` 的 `allowed`。
注意这时配色块数量会变成 3 × 3 = 9 块，**每加一条轴，块数是乘法增长的** ——
这是双轴矩阵的固有成本，加之前先想清楚是否值得。

### 换文案

界面文案分散在两处：

- **静态文案**（标题、按钮、占位符）在 `index.html` 里直接改；
- **动态文案**（各种提示与报错）集中在 `js/app.js` 的 `MSG` 对象里，一处修改全局生效。

### 调整解析上限

```js
// js/app.js
const MAX_LEN = 5 * 1024 * 1024;   // 单次可接纳的密钥上限（字符）
const MAX_LEN_LABEL = '5 MB';      // 超限报错文案里展示的写法
```

上限是**按字符数**计的。密钥是纯文本，一个字符基本对应一个字节，
所以 5 MB 的密钥约能解出 3.7 MB 的原始内容。

界面上**只有一处**会出现这个数字：真的超限时那条报错
（`密钥体积过大（超过 5 MB），请确认内容是否正确。`）。
输入框与页脚都不再展示任何体积说明 —— 改上限时只需要同步 `MAX_LEN_LABEL` 一处，
报错文案会自动跟着变。

改小可以防止误粘贴超大文件；改成 `Infinity` 则不加限制。
实测解码本身很快（5 MB 密钥约 20–30 ms），真正的性能瓶颈在超大数据下的
`execCommand` 复制兜底，所以**不建议**把上限调得远大于 5 MB。

### 改品牌名

搜索替换 `激活盒子` 即可（`index.html` 的 title / h1 / 品牌副标题 / 页脚，
以及 `js/app.js` 顶部注释）。另外两个 JS 文件里的两个存储键
（`activation-box-theme` / `activation-box-mode`）建议一并改掉，避免和别的项目串味。

> 项目所在文件夹名 `Activation Box` 属于文件系统路径，不在界面文案范围内，无需改动。

## 常见问题

**Q：为什么这个页面不叫"Base64 转换器"？**
A：这是刻意为之。目标用户不一定懂编码，他只知道手里有一段"激活密钥"要变成"激活内容"。
用主题化措辞（盒子 / 激活）能让界面自洽，也让分享出去时不显得像个开发调试页。
底层实现没变，只是把技术名词收进了代码里。

**Q：默认是什么样子？**
A：白底、深色文字、绿色强调色的「森林绿 · 白天」。首次打开就是它，不需要点任何按钮。
如果你切换过外观，下次打开会恢复你上次的选择（存在浏览器本地）。

**Q：「白天」和「橙渐白」有什么区别？不都是浅色吗？**
A：白天是**明度**，橙渐白是**色相**。它们分属两条轴，所以"橙渐白 · 白天"和"森林绿 · 白天"
都是白底，但强调色一个是暖橙、一个是深绿。而"橙渐白 · 黑夜"则是深色底 + 暖橙强调色。
三条白天配色共用纯白底，是为了让"白天 = 白纸"这条承诺足够干脆。

**Q：为什么"白天/黑夜"要单独做成一条轴，而不是直接多给几个颜色选项？**
A：因为色相和明度是两件独立的事。做成一条轴之后，用户能表达"我要紫色系，但白天用"
这种组合；如果把它们揉成 6 个并列的颜色选项，选项会又长又难认，
而且每加一种颜色就要多加两个选项。

**Q：在手机上会不会显示不正常？**
A：项目针对 PC / 平板 / 手机三档做了适配，并在 7 种视口下实测过（见
[响应式布局](#响应式布局)）。手机上的关键处理包括：两条轴换行撑满、
主按钮撑满整行、点击目标放大到 40–48px、输入框字号提到 16px 避免 iOS 聚焦放大、
四周叠加刘海屏安全区、键盘弹出时用 `dvh` 重新计算文本域高度。

**Q：为什么我在电脑浏览器里把窗口拖到 400px 宽，看起来是溢出的？**
A：多半不是页面问题，而是浏览器本身的限制。Windows 上的 Chrome / Edge（包括无头模式）
会把窗口宽度**强制不小于约 500px**，所以你看到的其实是"页面按 500px 排版、然后被裁到 400px"。
要看真实的窄屏效果，用手机的开发者工具（F12 → 设备模拟）或者直接用真机访问。

**Q：换外观时为什么颜色是"渐变过去"的，而不是瞬间变？**
A：这是刻意设计的过渡动画。全站统一 `.36s` 缓出，所有部件同步收放。
如果你不喜欢，把 `css/style.css` 里 `:root` 的 `--t-dur` 改成 `.01s` 就变成瞬时切换了。

**Q：换外观会不会很卡？**
A：不会。JS 只改一个 HTML 属性，动画完全由 `background-color` / `border-color`
这类合成成本很低的属性承担，不涉及布局重排（reflow）。即使在手机上也是 60fps。

**Q：外观选择存在哪？会同步到别的设备吗？**
A：存在当前浏览器的 `localStorage` 里（两个键分别存色相和明度），不会同步、不会上传。
换设备或换浏览器就是默认的「森林绿 · 白天」。

**Q：隐私模式下外观能记住吗？**
A：可能记不住（部分浏览器在隐私模式下会禁用 `localStorage`）。
代码里读写都包了 `try/catch`，记不住就静默降级为默认外观，不会报错、不会白屏。

**Q：刷新页面会先闪一下默认外观吗？**
A：不会。`js/theme-init.js` 会在浏览器首次绘制之前把两个属性都写好，
所以无论你选的是哪套组合，都不会看到闪烁 —— 尤其是从白色切到深色时那一下刺眼的反差。

**Q：点了色相，为什么明暗模式没有被重置？**
A：因为两条轴完全独立，各存各的键、各写各的属性，互不干涉。

**Q：点「启动激活」后提示"自动复制被浏览器拦截"，是坏了吗？**
A：没坏。结果已经正常解析并显示在框里了。这是浏览器在非安全上下文（比如直接双击打开的
`file://` 页面）下对剪贴板的策略限制。点一下「复制结果」按钮，或者本地起个静态服务器
（见[快速开始](#快速开始)的方式二）就能恢复自动复制。

**Q：粘贴时带了换行和空格，会解析失败吗？**
A：不会。换行、空格、制表符、全角空格都会在解析前被清理掉，这是最常见的粘贴污染。

**Q：我的密钥末尾没有 `=`，能行吗？**
A：可以。尾部填充会被自动补齐；反过来多写了几个 `=` 也会被先剥掉再重新补齐。

**Q：密钥里有 `-` 和 `_`，报错了怎么办？**
A：不用处理，直接被支持 —— URL 安全字符集会被自动还原后再解析。

**Q：中文解析出来是乱码？**
A：正常不会。解析器优先按严格 UTF-8 解码，中文和 Emoji 都能正确还原。
如果确实遇到乱码，那说明这份密钥里装的本来就不是 UTF-8 文本。

**Q：密钥会上传到服务器吗？**
A：不会。整个项目没有任何网络请求代码 —— 没有 `fetch`、没有 `XMLHttpRequest`、
没有外部 CDN 和字体。你可以断网打开页面验证，功能完全不受影响。

**Q：能离线使用吗？**
A：能。这正是它零依赖的价值：拷进 U 盘、塞进内网、丢进离线环境，双击就能跑。

**Q：输入框里能直接粘贴二进制文件吗？**
A：不能，只接受文本。单次最多 5 MB，超过会被拦截并提示，这是为了避免超大字符串把页面卡死。

**Q：5 MB 会不会很慢？**
A：不会。实测一份正好 5 MB 的密钥（5242880 个字符），能正确解出 1310720 个中文字，
解码本身在 20–30 ms 量级，用户感知不到等待。真正的开销在把结果写进只读框、
以及复制到剪贴板，也都在一瞬之间。超过上限才会被直接拦下，不做任何解码。

## 隐私与安全

- **数据不出本机**：没有后端、没有埋点、没有第三方资源，密钥内容不离开浏览器。
- **不落盘**：密钥与结果只存在于内存中的 DOM 里，关闭标签页即消失。
  `localStorage` 仅用于保存两项：主题颜色与明暗模式。
- **不使用 `innerHTML` 渲染用户内容**：结果通过 `textarea.value` 写入，
  天然免疫 XSS —— 即使密钥里解析出 `<script>` 标签，也只会作为纯文本展示。
- **不吞异常**：所有可能失败的操作（`atob`、剪贴板、`localStorage`）都被显式捕获，
  失败时给用户明确反馈，而不是静默失败或白屏。
